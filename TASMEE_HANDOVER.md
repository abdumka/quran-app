# Tasmee (التسميع) handover

Written 2026-09-21, when branch `big` was merged into `main`.
Audience: whoever continues the Tasmee feature in this repo (the owner, or an AI assistant starting cold).

Tasmee is a recitation-memorization test. The page is covered, the user recites from memory into the
microphone, and words uncover as they are recited correctly. Mistakes stop the session at the word.
Everything runs on the device. Riwaya: Qalun (سكون وقصر), Libyan mushaf, 602 pages.

## 2. How the feature works

### 2.1 Pipeline

1. **Recognizer.** Streaming Zipformer2-CTC phoneme model (Quran-Lab `zipformer_p_arabic_v3.1` int8,
   251 tokens) through `sherpa_onnx`, decoding about every 100 ms in a worker isolate
   (`lib/services/zipformer_recitation_engine.dart`). The model is downloaded once from R2
   (`AsrModelManager`). Licence NPL-1.2: the feature must stay free and without ads.
2. **Tracker** (`lib/utils/phoneme_tracker.dart`, `PhonemeTracker`). An online edit-distance DP of the
   heard phonemes against the page's expected phoneme string. It records, per cell, where the best path
   last restarted, so repeats are re-judged from their first sound.
3. **Judge** (`VerdictTracer` in the same file). Per word: `ok`, `unsure`, `wrong`, `skipped`, `pending`,
   with a reason for `wrong`: `hafs`, `word`, `extra`, `haraka`, or plain distance.
4. **Session** (`lib/services/memorization_test_service.dart`). Turns verdicts into word statuses, holds,
   page flow, reports, logs.
5. **Overlay** (`lib/widgets/quran/memorization_test_overlay.dart`). Paints word masks over the page image
   and the session bar.

A Python mirror of steps 2 and 3 lives in `D:\quran app\tasmee_work\zipformer\eval_session.py`.
**Every change to the tracker or judge must be made in both** and checked with the parity fixtures
(section 5).

### 2.2 Session rules

- **Where the session starts is the only free choice.** The first sounds may land on any ayah of the
  page. After that there are no forward jumps.
- **Mistake:** the session holds at the word (pink mask, vibration or tone). It is released when the word
  is re-read correctly (verdict `ok`, or distance at most 0.3), by a help button, or after 12 correct
  words further on.
- **Skipped words:** one skipped word is a soft hold like a mistake. Two or more, or a whole ayah, is a
  **hard stop**: the tracker is rebuilt at the held word (`startWord`) behind a barrier (`maxCell` = end of
  that ayah). Only reciting from the held word or a help button continues. A mistake hold *hardens* when
  the words after it come back skipped, because a skipped ayah first looks like a wrong first word.
- Nothing is held before the first correct word has fixed where the user started.
- A page does not complete while a word is held.
- When a page completes the engine keeps running, the text under it is swapped to the next page, and the
  view flips (`pageAdvanced`). Each page is its own log session.
- Help buttons: كلمة (reveal one word), الآية (reveal the ayah), أعد الآية (the ayah becomes unread again and
  the tracker is rebuilt at its first word), تخطَّ, الصفحة, إنهاء, إخفاء.
- The bar shows only: silence, a mistake, skipped words, "not on this page", engine error, page complete,
  and the drill label. Every other message goes to the log only (`feedback` event with `shown: false`).

### 2.3 Judge rules worth knowing

- `okDistance` 0.15, `unsureDistance` 0.4. `unsure` reveals the word. An over-long heard form
  (1.4 times the word or more, distance above 0.3) is `wrong`, not `unsure`.
- **`hafs`**: the heard form is closer to the word's Hafs form than to the Qalun form.
- **`word`**: the heard form is another Quran word. Three ways in: nearest lexicon entry (above the ok
  band), *exactly* another lexicon word inside the ok band (يحشرهم for نحشرهم), or a look-alike alternative.
- **`extra`**: a whole extra word in the gap between two words.
- **`haraka`**: the final short vowel differs, judged only when the user read straight on into the next
  word (no pause, no merged consonant).
- **Accepted forms** beat all of the above.

### 2.4 The expected-phoneme data: `assets/data/page_phonemes.json`

One entry per page, per ayah, per word:

```
[ text, phon, tanween, taMarbuta, hafsAlt, wasl, alts, accept ]
```

- `phon`: Qalun phonemes. `hafsAlt`: the Hafs form **when the Hafs check is ON for this word**.
- `alts` (index 6): look-alike (mutashabihat) alternatives, mined from the mushaf text: other words the
  Quran has between the same previous and next word. 13,552 words have some.
- `accept` (index 7): forms that are equally correct. Mostly "what the model produces for a correct Qalun
  reading when it cannot hear the Qalun feature".

Other assets: `phoneme_lexicon.json` (28k phoneme strings), `word_masks.json` (word ink rectangles per
page, plus the page's placement inside the هوامش image), `audio/tasmee_alert.wav`,
`images/hifz_tools_icon.png`.

### 2.5 Other parts

- **Reports** (`tasmee_report_store.dart`, `tasmee_reports_page.dart`): one JSON per recited page.
- **Alerts** (`TasmeeAlert`): vibrate+sound / vibrate / sound / none, via `vibration` and `audioplayers`.
- **تقوية الحفظ** (`tasmee_weak_point_store.dart`, `tasmee_weak_points_sheet.dart`): every error feeds a
  pool keyed `surah:ayah:word`. A drill starts up to two ayahs before the mistake (on the previous page
  when the target opens its page), ends when that ayah is done, and a correct reading removes the point.
  Opens once 3 points exist; 10 ayahs a round.
- **Logs** (`tasmee_session_recorder.dart`, `tasmee_upload_service.dart`): audio + JSONL per page session,
  uploaded to the R2 bucket `tasmee-sessions`. Keep 50 by default. The owner wants logging kept as rich as
  possible for now, to be trimmed before production.
- **Mask review site**: Cloudflare Worker `tasmee-mask-review` at `https://review.mushaf-qaloon.com`
  (reports in the `quran-content` bucket under `mask-reports/`).

## 3. The sheikh audit, and the Hafs / Qalun check

This is the part most likely to be misunderstood.

Two Qalun recitations were decoded with the app's own model and replayed through the judge. A sheikh's
correct recitation should raise no flags, so every flag is a false alarm of the pipeline.

| Reciter | Coverage | Words | Flagged |
|---|---|---|---|
| Abdulhamid Al-Qryw (the app's reciter `alqryw_qaloun`) | whole Quran | 76,584 | 110 (0.14%) |
| Alnaihi (per-ayah MP3s) | about 40% (the rest would not download from OneDrive) | 38,790 | 99 |

What it showed:

- **The model leans to the Hafs form**, and both sheikhs give nearly the same rate per kind of
  difference, so it is the model and not a reciter. Heard as Hafs from a Qalun sheikh:
  وَهْوَ about 75%, اتخذتم 100%, the eased hamza (أرٰيتم) about 55%, the opened ya (إنيَ) about 25%, and also
  real word differences such as يحسِب, ضُعف, هزؤًا, كفؤًا, وإنه in al-Jinn.
- **Policy** (`tasmee_work/alqryw/hafs_policy.py`): the Hafs check is ON for a word unless a sheikh
  instance of that word was heard as the Hafs form, or it is an eased hamza, or its kind of difference is
  known bad and the word has no clean evidence of its own. Clear differences stay ON even when they are
  one of a kind. **ON for 453 words, OFF for 701.** Where it is OFF the Hafs form is an accepted form, so
  a real Hafs slip there is not caught. That is a limit of the model.
- About 90 words failed for **both** sheikhs the same way: errors of the expected phonemes, mostly forms
  carried over from Hafs by the generator (يَصَّالَحا, مساكين, قَيِّمًا, لَمَا, أُكْلُه, تُكفروه), the short pronoun
  of نُؤتِهِ / يُؤدِّهِ, أَٰ۟ذا / أَٰ۟له, and a second hamza turned ya. They are fixed as **accepted forms**, not yet
  in the generator.
- `D:\quran app\tasmee_work\hafs_qalun_differences.md` lists all 1,154 known differences page by page with
  ✅ (detected) or ⚪ (not detectable), for self-testing.

**Order to regenerate the data** (each step rewrites `page_phonemes.json`):

```
naihi/apply_audit.py --write
alqryw/learn_from_sheikhs.py qryw=... naihi=... --write
alqryw/hafs_policy.py        qryw=... naihi=... --write
alqryw/clean_forms.py --write
zipformer/add_mutashabihat.py --write          # always last
zipformer/make_fixture2.py --write             # then refresh the parity fixture
```

`hafs_policy.py` reads the *original* Hafs forms from git commit `fb04503`. That commit must stay
reachable.

## 6. Gotchas

**Process**

- Never edit or commit `update.json`. The owner does it by hand after a store release.
- Never paste secrets in chat. Credentials live only in gitignored files: `tools/r2_upload.json`,
  `tool/tasmee_r2.txt`, `quran-app-main\tools\.r2_secret`.
- Do not trade detection for fewer false alarms silently. When a check is switched off, say what is lost.
  The owner cares a great deal about telling Hafs from Qalun.
- Do not invent linguistic claims. One false "you read this as Hafs" message came from a generator
  artifact. Check against a Qalun recitation before flagging a class of words.

**Code and data**

- Tracker and judge exist twice (Dart and Python). Change both, then run both parity tests.
- `ValueNotifier` is silent when set to an equal value. `pageAdvanced` pulses through 0 for that reason.
- The replay tools print only the *last* verdict per word, which over-counts mistakes compared with the app
  (the app ignores later verdicts for a word already correct). Use `trace_log.py` for what happened first.
- The original Hafs forms in the asset contain about 50 entries from a misaligned ayah (8:71 carried words
  of 8:1). `clean_forms.py` drops any form further than 0.55 from its word. The generator
  (`zipformer/validate_qalun.py`) still has that pairing bug.
- A long-vowel or nasal run is collapsed (`collapseMadd`) before comparison; the asset stores the
  uncollapsed form.
- The model often drops the first sound after a silence (وَيوم heard as يوم, first word of a session).
- The model confuses و and ف at word start now and then (4 in 39k sheikh words), which limits how strict
  ومن / فمن can be. Single-consonant confusions that land on a real word cost about one false stop per
  1,000 words.

**Tooling on this machine**

- Bash heredocs that contain Arabic diacritics fail to parse, and so did one with an apostrophe inside a
  quoted block. Write such scripts to a file and run them.
- A command containing the literal text backslash-u-0000 is rejected.
- Python `write_text` turns LF into CRLF on Windows. Write bytes.
- The CDN returns 403 to Python `urllib`. Use `curl`.
- OneDrive cloud-only files cannot be read by tools here ("cloud sync provider failed"). When the owner
  pastes an image in chat, it can be recovered as base64 from the session transcript `.jsonl`.
- Drive D: filled up once during a 2 GB download. Put large downloads on C:.
- Running the regression, an audit and `flutter test` at the same time starved the machine; a `flutter
  test` hung for 20 minutes. Run heavy jobs one at a time.
