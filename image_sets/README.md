# Page image sets

The app bundles **one** set of 602 `page_*.webp` images in
[`assets/images/`](../assets/images): the full هوامش (margin) scans, about
139 MB. Both reader views come from that one set — with "عرض الهوامش" off the
reader crops each page to its frame interior at render time
(`lib/widgets/quran/page_image_crop.dart`, rects in
`lib/data/page_crops.dart`, generated by `tools/generate_page_crops.py`);
with it on, the whole scan is shown. Nothing is downloaded any more.

The margin scans' master copy is
`D:\OneDrive - Oregon Health & Science University\Del\jam\pages_changed`
(edits to a page go there first, then get copied into `assets/images/`).

## `high_fidelity/` — the old 720x1640 set (tooling only, NOT bundled)

Until 1.5.2 this was the bundled set: each file is the frame interior of the
matching هوامش page, resampled to 720x1640 (about 1.70x squeezed horizontally,
1.07x vertically; the reader draws pages with `BoxFit.fill`, which is why the
squeeze was never visible). The ayah/word region data under `assets/data/`
is expressed in ratios of *these* images, so the generators keep reading
them from here:

- `tools/generate_word_masks.py`, `tools/generate_ayah_regions.py`,
  `tools/generate_word_regions.py`, `tools/page_furniture.py`,
  `tools/sample_paper.py`, `tools/build_page_spans.py`.

If a page is ever re-cut, regenerate this set from the هوامش scan with the
`hw` rect (see `tools/refit_hawamesh.py` and
`D:\quran app\tasmee_work\hawamesh_transform.py`), then rerun the generators.
